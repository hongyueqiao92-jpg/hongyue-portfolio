01 / BACKGROUND & CHALLENGE

业务走向海外，操作习惯不能直接平移

2025 年，随着 Keeta 国际化业务拓展，营销运营需要通过 Persona 完成人群圈选。为控制初期成本与交付时间，产品先将国内版本删减功能后迁移至海外。

但海外用户、业务与团队环境不同。原有复杂规则、分散入口与不准确的英文表达，带来了理解门槛、操作低效和配置出错的风险。国际化需要重新理解任务，而不只是替换界面语言。

02 / APPROACH

先理解用户如何工作，再确定设计改进的重点

前期我主动与业务、产品对齐，主导用户调研与访谈；产品协助寻找目标用户及研究资源。从海外业务、用户和产品三个角度识别问题，推动设计方向与优先级讨论。

设计目标是“易学、易用、少出错”。它对应三条改进路径：帮助用户理解规则、整合任务流程，以及让信息表达贴近业务语境。

03 / KEY DESIGN · RULES

让抽象规则可理解，让修改发生在原处

从配置规则，到看懂圈选结果

通过预置规则组降低起步门槛，并增加规则解读区：将组间关系与圈选结果用韦恩图直观表达。用户配置条件时，可以同时理解这些条件如何影响结果。

两层分组与原地编辑，减少反复拆改

保留默认规则组确认，将复杂规则组织为两层分组，让用户直接修改组内条件。前后对比展示了从多层嵌套、反复拆组，转向随配随改的处理方式。

04 / KEY DESIGN · WORKFLOW

从选择产品功能，转向完成圈选任务

圈选方式从 11 种整合为 2 种

整合“规则圈选”与“已有人群”两条核心路径，将标签、事件及已有资产纳入统一入口，减少用户在多个圈选方式之间判断和跳转。

先添加条件，再逐步完成配置

将“先选方式、再找标签、再配规则”的前置规划，调整为从添加条件开始、逐步选择和即时反馈的交互。设计意图是让用户边做边理解，减少反复返回选择入口。

05 / AI & LOCALIZATION

翻译业务含义，而不只是翻译字面

机器翻译难以准确传达业务含义。我将 AI 辅助翻译与人工校验结合，从全场景文案、业务语言和信息呈现三个层面减少理解偏差。

翻译判断沿用“精准、地道、简洁”：先校验中文原意，再借助 AI 生成候选表达，结合业务场景人工确认。相关经验沉淀为翻译 Agent Prompt / Skill，并复用于国内 Persona 文案优化。

精准 · 识别业务含义
Availability → Eligibility

“可领”表达领取资格，而非是否可用。

地道 · 使用行业表达
Modify validity period → Edit expiration date
简洁 · 去除重复表达
Basic information configuration → Segment configuration

06 / IMPACT & REFLECTION

从上线前验证，到上线后的持续跟进

7 人可用性测试，将问题带回方案

上线前邀请 7 位用户参与可用性测试，在获得正面反馈的同时继续修订细节。测试后的调整包括结果实时联动，以及增强 OR 关系的可识别性。

测试口径：不考虑数据、性能等情况下，任务均时长缩短 3.1 分钟，其中最快 3.5 分钟完成。与下方上线后结果分开理解。
